# 知识温度计（Memory Climate）需求文档

> 文档状态：产品需求草案
>
> 目标版本：下一阶段迭代
>
> 关联现有实现：`MemoryClimateEngine`、`MemoryClimateCard`、
> `MemoryClimateHistoryStore`、`ClimateInterleavingEngine`

## 1. 背景

StudyPulse 已经能够记录成绩、错题复习结果、掌握度和考试时间，但用户仍需要自己判断：

- 哪些科目正在遗忘；
- 哪些知识点只是最近答对，尚未稳定掌握；
- 哪些概念容易相互混淆；
- 今天最值得优先投入哪一小段时间。

“知识温度计”把这些分散信号整理成一个低认知负担的状态提示。它不试图给出绝对的“掌握率”，而是回答一个更适合日常使用的问题：

> 哪个科目需要我现在关注，以及原因是什么？

## 2. 产品目标

### 2.1 目标

1. 在主页上用一张卡片让用户快速发现最需要关注的科目。
2. 解释状态形成的证据，避免只给出没有依据的颜色或标签。
3. 将发现转化为可执行的复习入口，减少从发现问题到开始行动的步骤。
4. 使用本地、确定性的规则运行，不要求网络或 LLM 配置。
5. 随学习阶段分别记录历史，避免不同考试阶段的数据相互污染。

### 2.2 非目标

- 不替代成绩趋势图、错题 SRS 或考试倒计时。
- 不声称精确预测考试成绩或真实记忆强度。
- 不在 MVP 中新增社交排名、排行榜或跨用户比较。
- 不要求读取新的 HealthKit 数据。
- 不因一次答错就把整个科目标记为高风险。

## 3. 用户与使用场景

### 3.1 目标用户

StudyPulse 的中学生、高中生和备考用户，尤其是同时管理多个科目、错题数量较多的用户。

### 3.2 用户故事

- 作为学生，我打开主页时，希望立即知道今天最应该复习哪个科目。
- 作为学生，我看到一个科目变冷时，希望知道是因为太久没复习、反复答错，还是复习已逾期。
- 作为学生，我发现两个概念互相干扰时，希望直接进入一组交错复习题。
- 作为学生，我没有很多时间时，希望获得一个 15 分钟以内的最小补救动作。
- 作为学生，我切换学习阶段后，希望只看到当前阶段相关的知识状态。

## 4. 核心概念

### 4.1 科目级状态

系统为每个有足够复习证据的科目生成一个 `SubjectMemoryClimate`。状态不是连续温度数值，而是带风险顺序的可解释天气状态。

状态从高风险到低风险的顺序为：

1. **雷暴（thunderstorm）**：检测到两个相关概念都存在近期负向回忆证据，优先处理概念干扰。
2. **冻结（frozen）**：知识长期没有被调用，或 SRS 队列严重逾期。
3. **雾（fog）**：已有复习证据，但掌握度、复习稳定性或逾期情况不足以判定为安全。
4. **湿热（southHumid）**：近期刚答对，但掌握度偏低、重复次数少，或近期出现过遗忘，说明状态可能不稳定。
5. **晴朗（clear）**：掌握度较高、最近两次复习稳定且逾期比例较低。

### 4.2 置信度

每个科目状态必须携带 `confidence`，范围为 `0...1`。置信度用于辅助展示，不得被文案表达为医学、统计或考试保证。

当复习证据不足时，系统不生成该科目状态，而不是生成一个低置信度的误导性结论。

### 4.3 概念热点与干扰

系统从错题标签或本地知识节点中提取概念：

- 同一道错题中共同出现的两个概念，可形成候选关联；
- 只有两个概念都存在近期 `hard` 或 `again` 记录，且负向回忆总次数达到最低阈值时，才可标记为干扰；
- 干扰结果必须关联证据错题 ID，供详情页解释和后续复习使用。

## 5. 数据输入与规则

### 5.1 输入数据

- `MistakeNote.subject`
- `MistakeNote.tags`
- `MistakeNote.masteryScore`
- `MistakeNote.masteryHistory`
- `MistakeNote.reviewState`
- `MistakeNote.date`
- 当前 `phaseId`
- 当前时间和系统日历

成绩、HealthKit 和学习会话可以继续用于其他建议系统，但不作为知识温度计 MVP 的必要输入。这样可使结果更聚焦于“知识是否正在被遗忘”。

### 5.2 最低证据要求

- 科目没有错题：不显示知识温度。
- 科目只有未复习、没有掌握历史的全新错题：不显示知识温度。
- 科目至少有两条掌握历史，或已满足长期冻结条件：允许生成状态。
- 空数据状态必须显示友好空态，不显示“晴朗”。

### 5.3 关键默认阈值

以下阈值为当前实现和需求基线，必须集中定义在纯函数引擎中，并通过单元测试覆盖：

- 近期负向证据窗口：30 天；
- “刚刚复习”窗口：48 小时；
- 冻结判定的中位未调用时间：21 天；
- SRS 逾期宽限：7 天；
- 雷暴至少需要 3 次相关负向回忆，且两个概念各自都必须有负向证据；
- 晴朗要求平均掌握度至少 0.70、最近两次复习稳定、逾期比例低于 0.20。

阈值不应直接散落在 View 或 ViewModel 中。未来调整阈值时，应同步更新产品文档和测试。

### 5.4 确定性与排序

- 相同输入、相同时间和相同日历必须产生相同结果。
- 科目按风险等级、置信度和本地化名称稳定排序。
- 任何字典聚合必须防御重复键，不使用可能因重复键崩溃的唯一键初始化器。
- 当前阶段过滤应在生成前完成。

## 6. 页面需求

### 6.1 主页卡片

卡片默认启用，遵循现有 Home 卡片排序和启用机制。

卡片必须包含：

- 标题“知识温度计”或对应本地化文案；
- 当前风险最高的科目；
- 对应天气图标和状态标签；
- 一句简短、可解释的摘要；
- 最多展示 4 个科目的横向状态标签；
- 点击卡片进入详情页。

卡片没有可展示科目时应隐藏，而不是占据空白区域。

### 6.2 详情页

详情页以 sheet 形式打开，支持 iPhone 和 iPad，包含：

1. **今日状态**：列出当前阶段所有有证据的科目、状态、摘要和置信度。
2. **90 天历史**：按科目展示每日状态热力图；没有数据的日期使用中性空态色，不得等同于晴朗。
3. **证据与热点**：展示主要概念、概念干扰、负向回忆次数和相关错题依据。
4. **开始复习**：进入错题闪卡复习；若存在雷暴干扰，优先使用交错复习队列。
5. **无数据说明**：解释需要先记录错题复习，不能要求用户额外配置。

### 6.3 15 分钟补救任务（下一阶段）

当最高风险为冻结、雷暴或雾时，详情页提供一个“15 分钟补救”入口：

- 优先选择最高风险科目；
- 雷暴优先选择相关概念的一组交错卡片；
- 冻结优先选择最早逾期或最长未调用的错题；
- 雾优先选择最近一次答错或掌握度最低的错题；
- 任务预计时长不超过 15 分钟；
- 完成后不自动修改成绩，只记录正常的闪卡复习结果；
- 用户取消或跳过不计入学习成就。

该入口不能阻塞现有“开始复习”流程，若无法生成合适任务，应隐藏该入口并保留普通复习按钮。

## 7. 闪卡复习联动

### 7.1 现有行为

闪卡队列必须继续保证 SRS 到期卡的优先级，不得因知识温度联动而跳过到期卡。

### 7.2 概念交错

当存在雷暴状态时：

- 在到期卡之间插入少量同科目、相关概念的非到期卡；
- 插入数量最多为到期卡数量的 25%，且最多 3 张；
- 插入卡片必须标记为概念对照来源，方便调试和测试；
- 没有匹配卡片时退化为普通 SRS 队列。

## 8. 历史与阶段隔离

- 每日最多保存一个当前阶段快照。
- 同一天不同 `phaseId` 的快照必须分别保存。
- 历史保留最近 90 天，超出部分删除。
- 同一天、同一阶段重复写入必须更新而不是追加重复记录。
- 历史存储失败不能影响成绩、错题或闪卡功能；只记录日志并使用当前内存结果。
- MVP 使用版本化 JSON 存储，不新增 SwiftData 实体。

## 9. 本地化与无障碍

- 所有用户可见字符串必须加入 English、简体中文、繁體中文、日本語、한국어 五份主应用本地化文件。
- 天气状态、摘要、空态、按钮、历史提示和无障碍标签都必须本地化。
- 图标不能作为唯一信息，状态必须同时显示文字。
- 历史热力图每个色块必须提供科目、日期、状态或“无数据”的无障碍标签。
- 不依赖颜色单独传达风险等级；至少同时使用图标和文字。
- 遵循系统动态字体和 Reduce Motion 设置。

## 10. 隐私与失败处理

- MVP 所有计算在设备本地完成。
- 不上传错题、标签、掌握历史或阶段信息。
- 不新增 HealthKit 权限。
- 数据不足、JSON 损坏或读取失败时静默降级：隐藏卡片或显示空态，不弹错误提示。
- 日志不得记录错题正文、用户姓名或 API Key。

## 11. 技术约束

- 算法实现放在 `Services/MemoryClimateEngine.swift`，保持纯函数、无 SwiftUI、无 I/O。
- 展示模型放在 `Models/MemoryClimate.swift`，使用 `nonisolated`、`Codable`、`Hashable`、`Sendable` value type。
- 历史文件由 `Managers/Study/MemoryClimateHistoryStore.swift` 管理。
- 主页数据由 `HomeViewModel` 计算并通过现有 Home 卡片机制传递。
- 复习队列联动由 `ClimateInterleavingEngine` 负责，不在 View 中拼装队列。
- 新增 Codable 字段必须使用 `decodeIfPresent` 提供默认值。
- 新增算法逻辑必须同步添加 `StudyPulseTests/MemoryClimateTests.swift` 测试。
- 所有当前阶段相关查询必须使用当前 active phase，不能读取其他阶段的错题作为证据。

## 12. 验收标准

### P0：现有能力验收

- [ ] 有足够复习证据的科目能稳定生成五类天气状态。
- [ ] 新建且未复习的错题不会制造虚假的“晴朗”或“风险”状态。
- [ ] 雷暴只在两个概念均有近期负向证据时出现。
- [ ] 主页卡片能展示风险最高科目，空数据时隐藏。
- [ ] 详情页能查看今日状态、90 天历史、概念热点和相关证据。
- [ ] 当前阶段切换后，状态和历史不会混入其他阶段。
- [ ] 闪卡复习仍优先处理 SRS 到期卡。
- [ ] 历史重复写入可覆盖，同一天同阶段不会产生重复快照。
- [ ] 五种天气状态、空态和复习入口均完成五语言本地化。

### P1：补救任务验收

- [ ] 风险状态能生成不超过 15 分钟的补救任务。
- [ ] 雷暴补救任务优先覆盖关联概念。
- [ ] 冻结补救任务优先覆盖最长未调用或最早逾期内容。
- [ ] 任务完成只通过正常复习流程写入结果，不绕过 SRS 规则。
- [ ] 无合适内容时不显示误导性的补救任务。

## 13. 测试要求

纯函数测试至少覆盖：

- 晴朗、雾、冻结、湿热和雷暴的边界条件；
- 雷暴的双侧负向证据要求；
- 近期成功不能覆盖雷暴风险；
- 新未复习科目被忽略；
- 阶段过滤和同日快照更新；
- 90 天历史裁剪；
- 无到期卡、无匹配对照卡和普通队列回退；
- 15 分钟补救任务的科目选择、时长上限和空结果。

## 14. 发布与观测

首个版本不需要新增用户设置，默认作为主页卡片提供。发布后关注：

- 卡片点击率；
- 详情页“开始复习”转化率；
- 雷暴状态被打开后的复习完成率；
- 用户隐藏卡片的比例；
- 状态生成后 24 小时内的复习行为。

若用户频繁隐藏卡片或大量出现低置信度状态，应优先调整解释和证据门槛，而不是增加通知频率。

## 15. 实施拆分

### 阶段一：规格与稳定性

- 将现有 Memory Climate 行为与本需求文档对齐。
- 补齐边界测试、空态测试和阶段隔离测试。
- 检查五语言本地化和无障碍标签。

### 阶段二：行动闭环

- 增加 15 分钟补救任务模型和生成器。
- 在详情页加入补救任务入口。
- 将补救任务接入现有学习计时器或闪卡流程。

### 阶段三：趋势洞察

- 增加科目温度变化摘要，例如“连续 3 天降温”。
- 将温度变化与考试日期、成绩趋势结合展示。
- 仅在证据稳定且用户主动开启时考虑本地通知。
